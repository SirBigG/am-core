# Seller offers for related catalog cards

In Django Admin, **Related offer publications** controls seller visibility for the scoped related-catalog path. Add the existing Product, the Post it is already matched to, its CatalogEntity, the market country and the approved content language. The site follows the Admin instance and the editor needs its catalog publishing grant and the model permission. Enter package or unit text as supplied by the seller and enable the publication. The migration creates the table with no memberships. Existing marketplace routes continue to use their own policy.

All public cards come from the catalog selector. One aggregate query counts the corresponding active offers and distinct sellers for the card set. The offer must have an enabled membership for the current site, language, country, Post and entity. Its Post must be the selected catalog presentation. A manual match is required for non-varieties. Exact automatic name matches are accepted for cultivars under the existing case and whitespace rules. Active sellers, price freshness, known currencies and positive prices still apply. Future observations and inverted ranges are excluded. Each offer shows its original price or range and currency. A missing package label is reported as unspecified.

The generic `/agromarket/catalog-offers/` destination accepts a signed selection token created by the catalog adapter. It replays the originating card scope against current publication, active configuration and relation rules. Missing, tampered or out-of-context selections return 404. A qualifying card with no current offer returns an empty seller list. This route is noindex and no-store. The back link restores the original catalog filters and pagination. Existing `/agromarket/variety/<post-id>/` links keep their URLs and behavior. Broader market, company and other app site membership work remains in AGRO-9.
